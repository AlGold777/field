Новые идеи моделей, которые стоит взять:
- **Управление по когерентности** (GPT, Kimi): сила обработки зависит от межканальной когерентности, частоты и
  вероятности транзиента. Центр, бас и атаки защищены, рассеянное расширяется. Это не эффект, а «регулятор» всего
  процессора — снимает главный риск W1/W2 (развал центра).
- **Единый модуль «дистанции»** (Claude): D1 + D2 + D3 управляются одной координатой «расстояние», а не тремя ручками.
- **Быстрый путь + блочный путь** (Claude): M/S, DRR, EQ — посэмплово; W3/отражения — STFT. При нехватке CPU
  блочный путь отключается, быстрый остаётся (Kimi).
- **Глубина — перераспределение существующей энергии, а не синтез нового хвоста** (Kimi). Это и есть ответ на вопрос
  брифа «где граница с добавленной реверберацией».

## 2. Где модели согласны

1. **XTC не в основном треке.** Все 7. На широкой базе — закрыто; в ближнем режиме — отдельный эксперимент.
2. **Основная цепочка: W2 + W3/D4**, поверх — лёгкие D1/D3, W6/D2 как отключаемые модули.
3. **Процессор на Server до разделения каналов**, Point «тупой» (согласны все, никто не оспорил).
4. **Латентность** STFT 1024–2048 / шаг 512 = 20–40 мс, в запас 400 мс помещается с большим запасом.
5. **Мягким методам нынешней синхронизации хватает.** Важнее стабильность и симметрия, чем микросекунды.
6. **Согласование устройств обязательно** даже для мягких методов: минимально-фазовый регуляризованный EQ в общей
   полосе ~300 Гц – 8 кГц, без больших подъёмов в провалах, сглаживание 1/3 октавы, цель ≤ 1–1,5 дБ.
7. **Прототип сначала офлайн**, без кода приложения.
8. **Не делать:** Хаас, реверберация на весь микс, декорреляция баса/центра/транзиентов, стемы, настройка
   только в наушниках.

## 4. Чего модели не увидели (мои выводы)

### 4.1 Нынешняя синхронизация не «достаточна», а «на границе»
Корректор допускает ошибку до 125 мкс и исправляет шагами по 21 мкс — межканальная задержка **гуляет** в этом
диапазоне. На мягких методах это не разрушает эффект, но фантомный центр при сдвиге ~100 мкс смещается на несколько
градусов к опережающему телефону, и если ошибка «плавает», центр плывёт. Для процессора, который именно работает с
межканальными соотношениями (W2 меняет M/S-баланс по полосам), плывущий центр — первое, что услышат.
Поэтому: **дробная задержка + метрика остаточной ошибки — предусловие, а не опция.** Цель для основного трека:
≤ 50 мкс стабильно (95-й перцентиль за час), без ступенек.

### 4.2 XTC возвращается — но на одном телефоне, а не на двух
Главные блокеры XTC — синхронизация и различие динамиков. Оба исчезают, если XTC делать в **соло-режиме на одном
телефоне со стереодинамиками** (Xiaomi 14 Ultra): один ЦАП, одни часы, известная заводская геометрия, одинаковая
пара динамиков. Ровно так Apple делает пространственный звук на iPhone — бриф сам это отмечает (§4.2). Соло-плеер
(`docs/tz-solo-player.md`) даёт для этого платформу.
Поэтому исследовательская ветка XTC: **сначала один телефон в соло, потом (если сработает) два телефона в ближнем
режиме.** Redmi 14C, вероятно, с моно-динамиком — там этот режим недоступен; нужна проверка по устройствам.

### 4.3 Прототип не требует ни ПК-стенда, ни кода в приложении
Приложение уже играет стереофайл, раскладывая L/R по телефонам. Значит, обработанный офлайн WAV, добавленный в
очередь, звучит на паре **ровно так, как будет звучать встроенный процессор**, вместе с реальными ошибками
синхронизации и реальными динамиками. Варианты обработки — отдельные треки с кодовыми именами, ключ хранится
отдельно. Это слепой тест без единой строки кода в приложении.

### 4.4 Режимы пары и соло
- Stereo-пара: пространственный процессор работает.
- **Amplifier** (`tz-solo-player.md`, этап 2): оба телефона играют L+R — межканальной сцены нет, процессор
  **выключен** (или, для телефона со стереодинамиками, работает как в соло — позже).
- Соло на телефоне со стереодинамиками: база ~15 см → профиль «ближний», кандидат для XTC (п. 4.2).
- Соло в наушниках: бинауральная обработка — отдельная тема, в эту работу не входит.

## 5. Выбранное направление

```
стерео → анализ (когерентность, транзиенты) ─┬─ быстрый путь: W2 (M/S по полосам), EQ-согласование, уровень
                                             └─ блочный путь (STFT 2048/512): W3 прямой/рассеянный
                                                   → рассеянный: декорреляция (> ~300 Гц), D4, D3, [D1/D2 «дистанция»]
                                                   → прямой: без изменений
                     → сумма → лимитер с заглядыванием вперёд → L′ / R′ → Server играет L′, Point получает R′
```
- Всё на Server, одинаковая задержка обоих выходов, **обход (bypass) с выравниванием громкости** обязателен.
- Параметры расстановки (широкая база / ближний / соло со стереодинамиками) — профиль данных, не код.
- XTC — отдельный исследовательский модуль, сначала на одном телефоне.
