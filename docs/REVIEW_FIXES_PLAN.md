# План исправлений по результатам peer-review

Ветка: `claude/app-peer-review-ff9da5`. Базовый коммит: `fa2566c`.
Исполнители: 8 агентов, у каждого свой набор файлов (пересечений нет), каждый работает в собственном git-worktree и своей ветке `fix/<id>`. Интеграция, версии и документация — у ведущего.

## Общие правила для всех агентов

1. Менять **только файлы из своего списка «Владеет»**. Любой файл вне списка — не трогать, даже если там видна проблема: записать её в отчёт.
2. Не менять версионные константы (`versionName`, `versionCode`, `MARKETING_VERSION`, `CURRENT_PROJECT_VERSION`) и README. Это делает ведущий.
3. Каждый пункт плана — отдельный коммит: `git add <конкретные пути>` (не `git add -A`), сообщение `<id>-<N>: краткое описание`, в конце сообщения строка `Co-Authored-By: Claude Haiku 5.5 <noreply@anthropic.com>`.
4. Перед правкой **проверить пункт по коду**: часть замечаний ревью может оказаться неверной. Если дефект в коде не воспроизводится при чтении — не править, записать в отчёт «не подтверждено» с причиной.
5. Минимальный дифф. Никаких рефакторингов, переименований, форматирования чужих строк. Стиль, язык комментариев (русский) и плотность комментариев — как в окружающем коде.
6. Поведение iOS и Android должно оставаться идентичным по протоколу и константам. Если пункт затрагивает общий алгоритм (`core/*`), правка вносится в обе платформы в рамках одного агента (C) и тем же способом.
7. Не менять формат протокола (заголовки, JSON-ключи, константы). Исключение — явно названное в пункте.
8. Проверка:
   - Kotlin `core/*`: `cd android/coretest && KOTLIN_LIB=/private/tmp/sf-kotlin-lib sh run.sh` (должно закончиться `ALL PASSED`); после запуска удалить `out.jar`, не коммитить.
   - Остальной Kotlin: компилятора с Android SDK нет, поэтому код перечитать после правки целиком (импорты, типы, null-safety, потоки).
   - Swift: Xcode нет, только `swiftc -parse <файл>` для синтаксиса. Типы и API перепроверять чтением.
9. Отчёт в конце (до 40 строк): список коммитов (хеш, пункт), пункты «не сделано / не подтверждено» с причиной, что проверено и чем, что осталось непроверенным.
10. Не делать merge, rebase, push, не удалять ветки и worktree.
