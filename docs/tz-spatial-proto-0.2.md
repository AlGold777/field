Численная проверка принципа (шум, корреляция L/R 0,5):

| Операция | Корреляция L/R | Изменение моно |
|---|---|---|
| исходный | +0,50 | — |
| поворот фазы **только Side** на 45° / 90° | +0,50 | 0 (точно) |
| усиление Side +3 дБ | +0,20 | 0 (точно) |
| усиление Side +6 дБ | −0,14 (противофаза) | 0 (точно) |
| поворот L +45°, R −45° (0.1.x) | 0,00 | −1,76 дБ |

Вывод: **единственный способ расширить, не трогая моно, — менять Side (его уровень и его собственные задержанные
копии), не поворачивая Side относительно Mid.** Поворот Side не декоррелирует вообще; поворот L/R декоррелирует,
но разрушает моно. Отрицательная корреляция (Side > Mid) — это фазовость; её нужно ограничивать.

## 1. Архитектура 0.2.0: два слоя с разными инвариантами

```
L,R → STFT (2048/512, sqrt-Hann) → M = (L+R)/2, S = (L−R)/2
        ├─ слой ширины:  S′ = G_w(k,t)·S  (+ отражения из S, п. 2.3)      — M не трогается
        └─ слой глубины: M′ = G_d(k,t)·M                                  — S не трогается
      → L′ = M′ + S′, R′ = M′ − S′ → ISTFT → лимитер
```

| Слой | Что меняет | Инвариант (проверяется тестом, п. 6) |
|---|---|---|
| Ширина (W2, W6-S) | только Side | `L′+R′ = L+R` с точностью float (≤ −120 дБ) на **любом** сигнале |
| Глубина (D4, D3) | только Mid рассеянной части | `L′−R′ = L−R` точно; чистый центр `L=R` остаётся `L′=R′` точно |

Следствия по построению:
- центральная атака (S = 0) не может получить Side ни в одном варианте;
- слой ширины не может окрасить моно;
- всё, что меняет моно, сосредоточено в слое глубины и измеряется отдельно.

Вся обработка — в **одном STFT**, коэффициенты по бинам (без полосовых IIR и `sosfiltfilt`). Это убирает
предзвон двунаправленных фильтров (−45 дБ у W2_LO в отчёте) и даёт реализацию, переносимую в поток: у Server
400 мс опережения, поэтому STFT с задержкой ~43 мс и заглядыванием вперёд на ≤ 50 мс допустимы и в приложении
(записать в README как бюджет задержки будущей реализации).

## 2. Слой ширины

### 2.1 W2 — усиление Side по частоте, без маски когерентности
- `G_w(k) `: 1 ниже 300 Гц; `g_mid` в 300 Гц – 5 кГц; `g_hi` выше 5 кГц; переходы — плавные по логарифму частоты
  (полуокно косинуса шириной 1/3 октавы), без ступенек между бинами.
- **Маску когерентности убрать из W2.** Защищать центр не нужно (п. 0); маска только гасила эффект.
- **Ограничитель фазовости**: по сглаженным мощностям (время 80 мс, частота 1/3 октавы) —
  `G_w ← max(1, min(G_w, κ·√(P_M / P_S)))`, κ = 1,0 (конфиг). Side после усиления не превышает Mid → корреляция
  L/R не уходит в минус. Ограничитель только отменяет расширение, но **не сужает** исходник (`G_w ≥ 1`): если в
  записи Side уже больше Mid, она остаётся как есть.
- **Защита жёстко разведённых источников**: при |ILD| ≥ `ild_direct_db` `G_w → 1` (плавно, как в 0.1.1). Иначе
  инструмент только в L даёт противофазную копию в R (`R′ = (1−g)/2·L`).
- Варианты: `W2_LO` (+3 / +2 дБ), `W2_HI` (+6 / +4 дБ). Теперь они должны реально менять Side/Mid на музыке
  (ожидание: +1,5…+3 дБ в полосе 300 Гц – 5 кГц; записать в отчёт фактическое).

### 2.2 Рассеянное — дополнительное усиление Side
- `G_w(k,t) = G_w2(k) · (1 + (g_amb − 1)·m(k,t))`, где `m` — маска рассеянного (п. 3.2), `g_amb` = +2 дБ.
  Вместе с ограничителем фазовости п. 2.1 (применяется к итоговому `G_w`).
- Инвариант моно выполняется автоматически.

### 2.3 W6-S — ранние отражения только в Side
- Отражения строятся **из Side**, не из L/R: `r = Σ_i a_i · BP(S)(t − τ_i)`, полоса 500 Гц – 6 кГц, 3–4 отвода
  7–25 мс, −18…−14 дБ.
- Добавляются в противофазе: `L′ += r`, `R′ −= r`. Моно не меняется по построению.
- Реализация — в STFT как фазовый множитель задержки на кадрах с достаточным перекрытием, либо во временной
  области **каузальным** КИХ-фильтром с учётом общей задержки — выбрать и проверить тестом 6.1.
- Прежний W6 (перекрёстные отводы из рассеянной L/R) удалить.

### 2.4 Удалить
Фазовый декоррелятор `θ(k)` (`theta_max_deg`) — из кода, конфига и README (п. 0: он и есть причина окраски).

## 3. Слой глубины

### 3.1 D4/D3 — только Mid рассеянной части
- `G_d(k,t) = 1 − (1 − g_d(k))·m(k,t)`, где `g_d(k)` = −2 дБ (D4) с дополнительной полкой −2 дБ выше 8 кГц (D3).
- Применяется только к `M`. Side не трогается.
- **Гладкость по частоте**: `m` для слоя глубины дополнительно сглаживается по частоте окном 1/3 октавы — сужение
  моно не должно давать узких провалов (причина ripple в отчёте — маска меняется от бина к бину).

### 3.2 Маска рассеянного `m(k,t)` — защита по энергии и асимметричное сглаживание
- База — когерентность и ILD, как в 0.1.1.
- **Защита по энергии**: если мощность бина ниже −60 дБ от бегущего пика этой полосы (окно 1 с) или ниже −90 dBFS —
  `m = 0` (тишина не «рассеянная»).
- **Защита атак с заглядыванием вперёд**: детектор атак по полосам (1/3 октавы). Если атака в пределах следующих
  50 мс — `m` падает к 0 **до** атаки (минимум по окну заглядывания). После атаки `m` восстанавливается медленно
  (150 мс). Спад быстрый, подъём медленный — не симметричное сглаживание, которое и переносило вес на атаку.
- Проверка инвариантов после сглаживания (п. 6.2), а не только до.

## 5. XTC (часть B)

1. **Баг задержки**: убрать двойной сдвиг в `design_xtc_filters`/`apply_xtc`. Тест: импульс через XTC-фильтр при
   нулевом перекрёстном пути (модель без перекрёстного пути) — пик выхода на сэмпле пика входа ±1; метаданные
   `delay_compensated` вычисляются из фактического отклика, а не выставляются вручную.
2. **Расчёт на область, а не на точку**: фильтр — решение наименьших квадратов по сетке положений головы:
   дистанции 0,35 / 0,45 / 0,55 / 0,65 м × смещения −5 / 0 / +5 см. Варианты: `XTC_POINT_0.5` (как сейчас, на одну
   точку) и `XTC_REGION` × 3 регуляризации.
3. **Отчёт**: для каждого варианта — подавление перекрёстного сигнала (медиана и **худшая** точка) на **плотной**
   сетке проверки (0,3–0,7 м шагом 2,5 см × ±8 см шагом 1 см), отличной от сетки расчёта. Цель — не максимум в
   одной точке, а ≥ 10 дБ медианы в 1–4 кГц по всей области.
4. Ограничение, которое записать в отчёт: без измерительного микрофона реальные передаточные функции динамиков
   14 Ultra не измеряются; модель — точечные источники и сферическая голова. Итог даёт только слуховой тест.

## 6. Тесты-инварианты (обязательны; именно их не хватало)

### 6.1 Слой ширины (`W_LO`, `W_HI`, `W_LO_R`, `ANCHOR_OVER`)
На каждом из сигналов: музыка (все фрагменты), шумы с корреляцией 0 / 0,25 / 0,5 / 0,75 / 1, центральная атака
после тишины, стереоатака после тишины, жёстко разведённые источники, тишина:
- `max|(L′+R′) − (L+R)|` после выравнивания задержки ≤ −120 дБ относительно пика входа;
- центральный вход (L = R) → `max|L′ − R′|` ≤ −120 дБ.

### 6.2 Слой глубины (`W_LO_R_D` минус `W_LO_R`)
- Side не меняется: `max|(L′−R′)_D − (L′−R′)_без D|` ≤ −120 дБ;
- центральная атака после тишины: Side ≤ −120 дБ (следует из п. 1, но проверить);
- неравномерность формы моно высокого разрешения (Велч 8192, 300 Гц – 5 кГц, только бины выше −40 дБ) —
  ≤ 1,5 дБ пик-пик **после вычитания гладкой (1/3 октавы) составляющей**: гладкое снижение рассеянного — это
  задуманная глубина, узкие провалы — дефект.

### 6.3 Общие
- Предзвон: энергия до атаки (стереопакет после тишины) ≤ −50 дБ относительно пика атаки для всех вариантов.
- Фазовость: для `W_*` корреляция L/R по полосам 1/3 октавы на музыке и шумах не ниже 0 (кроме `ANCHOR_OVER`)
  и кроме полос, где она была ниже 0 уже во входе — там не ниже входной.
- ILD: жёстко разведённый источник в `W_*` — уровень в своём канале ±0,5 дБ, в противоположном ≤ −30 дБ.
- Лимитер: потолок −1,0 dBTP **строго** (усиление после лимитера запрещено; выравнивание громкости — до лимитера,
  затем проверка громкости; если выход за ±0,3 LU — повторная итерация, а не допуск).
- XTC — тест п. 5.1.

`evaluate_algorithms.py` (Astra) — включить в приёмку: пороги из этого ТЗ вынести в `config.yaml`, скрипт завершается
с ненулевым кодом при нарушении любого инварианта.
