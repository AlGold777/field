- **Файловый обмен.** №15 даёт доверенный канал для метаданных №17. №18, №57 и №62 задают жизненный цикл и graceful abort. №16 можно оценить после этого по фактическим throughput и задержке управления. №48, №168, №169 и №285 зависят от согласованного владения кэшем/декодером.

### Проверки, которые остаются открытыми

- **Основной обрыв, №21, №26, №44, №50, №91, №92, №112, №124, №216, №287.** Есть локальный debug APK кандидата, история воспроизведённого JVM-дефекта и 200 сохранённых тестов. Нет свежей синхронной записи двух физических устройств, исходных маршрута, моделей, источника и состояния сети в пользовательском инциденте. Проверить ≥90 с на сценарий по спецификации, в обеих расстановках Android/iOS. Если исходный инцидент на контрольной версии не повторится, вывод касается только пройденных сценариев.
- **Поведение ОС и интерфейса, №63/64/68/80/81/112/166/201/207/232/278/289/292.** Для мобильных сценариев нужны физический Android с проводным/BT выходом и iPhone, при наличии нескольких целевых версий ОС. Проверять результат действия: звук остановился, alert ушёл, trim применился, TalkBack/VoiceOver объявил действие, микрофон и рекордер освободились.
- **Численные заявления, №27/30/44/95/104/105/121/128/175/189/193/199/243/269.** Потребуются измерения на исходной и кандидатной сборках: +5% батареи, пиковое время и объём аллокаций, длительность/уровень артефактов, истинный overshoot и скорость офлайн анализа. Приведённые в запросе оценки сохранены как гипотезы там, где нет результата замера. Для лаборатории использовать фиксированный вход и хеши. №275 проверить на тишине и постоянном сигнале.

## Отклонённые идеи и причины

- **№68. Свайп Connect и рекомпозиция.** Ложная причина. Ключи именно свайпа Connect стабильны между обычными обновлениями UiState.
- **№70. Доступность действия «Сцена».** Устарело для данного Android. Есть прямое действие «Сцена». Проверка TalkBack остаётся в №207.
- **№88. KeyError pan_hard.** Устарело. Рендерер и анализатор понимают pan_hard, есть targeted fixture.
- **№115. Инкрементальный биномиальный хвост.** Микрооптимизация для восьми trial вне real-time. Приоритет у терминального контракта №110.
- **№155. Пауза пары при потере фокуса.** Положительное наблюдение об аудиофокусе. Использовать как сценарий приёмки без самостоятельной правки.
- **№171. MediaProjection FGS на API 26–28.** Неприменимо. Воспроизведение захвата на API 26–28 недоступно, штатный запуск ограничен API 29+.
- **№176. Безусловный START_STICKY.** Предложенный флаг не восстанавливает зависимые от процесса состояния. Согласованный lifecycle относится к №278.
- **№179. Переполнение live-кольца Spotify.** Кольцевое вытеснение — штатное, интервал 8–9 минут не подтверждён. Границы batch входят в №103.
- **№219. Эффект настройки keepaliveIdle.** У keepaliveIdle есть самостоятельная семантика. Недоказана избыточность текущего значения.
- **№227. Буфер под UDP 4096/65536 байт.** Предложенный 64-КиБ буфер не нужен формату с существенно меньшим максимумом пакета.
- **№237. Создание haptic на каждом движении.** Ложная частота. Haptic создаётся при входе в центр, а не на всех шагах.
- **№264. Ожидаемый NaN в normalization vectors.** NaN-входы уже покрыты. Для неизвестных входов формула задаёт численный выход.
- **№280. Гонка fileTransferOp.** У поля нет наблюдаемого читателя. Volatile не меняет поведение.
- **№281. PCM24 bit-exact и TPDF.** Подтверждённый принцип PCM24, без самостоятельного изменения. Нулевая или иная лежащая на сетке величина остаётся точной и после gain.
- **№284. Эвристика stereo по channelCounts.** Консервативный fallback для неизвестной возможности. Нужны наблюдения OEM для смены поведения, они входят в №44.
