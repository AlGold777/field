### R1 · P2 · Отправка UDP-аудио использует канал вне снимка воспроизведения

**Место:** [Engine.kt:5479](/Users/restart/Downloads/SoundField/android/app/src/main/java/app/soundfield/engine/Engine.kt:5479). Связанные участки: [смена каналов:4177](/Users/restart/Downloads/SoundField/android/app/src/main/java/app/soundfield/engine/Engine.kt:4177), [снимок для отправки:5487](/Users/restart/Downloads/SoundField/android/app/src/main/java/app/soundfield/engine/Engine.kt:5487).

В `packet(st, tl, …)` выбор канала изменён с `Ch.other(st.channel)` на глобальный `pointChannel`. Источник и эпоха берутся из неизменяемого `ServerPlayState`, а канал — из текущего изменяемого состояния другого потока. `sendLock` защищает отправку и повторную отправку друг от друга, но изменение `pointChannel` выполняется без этого lock.

Допустимая последовательность:

1. Поток `sf-tick` сохраняет старый `serverPlay`: Server играет L, Point должен получать R.
2. Поток `sf-engine` обрабатывает swap и меняет `pointChannel` на L.
3. Отправитель продолжает формировать пакеты старой эпохи, но читает уже L. Смена `serverPlay` на новую эпоху не меняет ранее сохранённый объект `st`.

**Последствие:** в старую эпоху могут попасть сэмплы противоположного канала. Повторная отправка тоже может реконструировать пакет с другим содержимым. Ошибка зависит от межпоточного чередования и не проявляется в обычной сборке.

Изменение появилось в версии с парным Solo. После замены этого режима независимым Solo необходимость читать здесь глобальный канал исчезла: сетевой sender работает только в паре, где локальный канал снова моно.

**Что исправить:** брать назначение Point из того же снимка, что источник и timeline; для текущей модели достаточно вернуть `Ch.other(st.channel)`. Если понадобится отдельное назначение при стереовыводе, хранить его в `ServerPlayState`.

**Подтверждение:** анализ потоков и порядка записей. На двух телефонах не воспроизводилось. Проверка при исправлении: UDP-пара, различные сигналы в L/R, многократный swap во время воспроизведения и retransmit.

### R4 · P2 · Фиксированные внутренние слоты не гарантируют неподвижность экрана

**Место:** [CSS:10](/Users/restart/Downloads/SoundField/docs/player-home-prototype.html:10), [pairView:99](/Users/restart/Downloads/SoundField/docs/player-home-prototype.html:99).

`body` центрирует `.phone` по вертикали через `display:grid; place-items:center`. У `.phone` задана минимальная высота, но нет постоянной высоты или верхнего якоря. В паре появляется блок баланса, в Solo он получает `display:none`.

Когда содержимое выше минимальной высоты, общая высота `.phone` меняется вместе с балансом. На достаточно высоком desktop-окне вертикальное центрирование меняет верхнюю координату всей `.phone` примерно на половину изменения её высоты. Вместе с ней перемещаются верхние кнопки, круги и плеер, хотя расстояния между ними внутри контейнера постоянны.

**Сценарий для визуальной проверки:** desktop viewport порядка 1000 × 1600, раскрытая очередь и EQ, переход Solo ↔ Point. Измерить `getBoundingClientRect().top` у `.phone`, `#pairButton`, `#speakerL`, `.track` до и после.

**Что исправить:** закрепить положение контейнера сверху либо задать стабильную высоту со скроллом внутри. Добавить проверку координат на широком и высоком окне.

**Подтверждение:** механизм следует из CSS и удаления блока из потока. Фактические координаты в браузере в этом review не измерялись.

### R5 · P2 · После удаления строки выделение указывает на другой трек

**Место:** [removeTrack:104](/Users/restart/Downloads/SoundField/docs/player-home-prototype.html:104), [выделение и массовое удаление:162](/Users/restart/Downloads/SoundField/docs/player-home-prototype.html:162).

`state.selected` содержит позиции строк. `removeTrack(i)` сдвигает очередь через `splice`, но не изменяет выбранные позиции.

**Воспроизведение:** очередь A/B/C → режим выделения → выбрать B → удалить A крестиком. Выбранный индекс `1` теперь относится к C. Массовое удаление удалит C вместо B.

**Что исправить:** хранить выбор по постоянному идентификатору трека либо корректировать все выбранные индексы при удалении. Android уже использует идентификаторы.

**Подтверждение:** обработчики выполнены в Node VM; после удаления A выделенным оказался «Синяя линия», хотя был выбран «Дорога домой».

### R6 · P2 · Массовое удаление останавливает даже не удаляемый текущий трек

**Место:** [deleteSelected:162](/Users/restart/Downloads/SoundField/docs/player-home-prototype.html:162). Для сравнения: [Engine.kt:4507](/Users/restart/Downloads/SoundField/android/app/src/main/java/app/soundfield/engine/Engine.kt:4507).

После любого массового удаления HTML безусловно выполняет `state.index=-1; state.playing=false`. Например, при воспроизведении A удаление только C убирает текущий трек из плеера и ставит воспроизведение на паузу.

В приложении оставшийся текущий трек сохраняется; при удалении текущего применяются правила выбора следующего. Прототип показывает другую логику.

**Что исправить:** сохранять текущий трек по идентификатору и пересчитывать его позицию; отдельно имитировать удаление текущего трека.

**Подтверждение:** воспроизведено исполнением фактического обработчика HTML в Node VM.

## 4. Что уже в приложении, а что пока только в HTML

Отдельного утверждённого backlog будущих изменений в прототипе нет. Наличие элемента в HTML само по себе не означает, что его новая компоновка уже согласована к переносу. Ниже разделены существующие функции, перенос на iOS и отличающиеся варианты HTML.

| Элемент или сценарий | Android | iOS | HTML и работа до согласования |
|---|---|---|---|
| Active и Disconnect с 7 символами имени, No/Yes | Реализовано | Реализовано | Имитируется. Нужно также показать длинные имена и не ASCII-символы |
| Connect: короткий клик к последнему телефону | Реализовано, запускается сетевое восстановление | Отдельной кнопки на главном экране нет | Соединение мгновенное; нет ожидания и ошибки |
| Компактный chooser, удержание/свайп вниз | Реализовано в состоянии Connect | Нет | Имитация есть. Список статический, нет пустого/первого подключения |
| Иконки телефонов без карточных плашек | Реализованы в новом Android-chooser | Старый экран подключения | Есть; это уже не исключительно будущая Android-работа |

Синтаксический разбор успешен. Полная компиляция SwiftUI и запуск не выполнены: активен `/Library/Developer/CommandLineTools`, полного Xcode в окружении нет. Parse не проверяет типы и layout SwiftUI.

### HTML

- Из HTML извлечён фактический JavaScript; `node --check` успешен.
- Фактический скрипт исполнен в Node VM с минимальной моделью DOM и управляемыми таймерами. Проверялись обработчики и состояние, без копирования их логики в тестовые реализации.
- **3 сценария прошли:** короткое нажатие Connect; удержание с подавлением завершающего клика; свайп вниз с подавлением завершающего клика.
- **6 сценариев выявили ошибки:** смещение выделения после удаления, остановка не удаляемого трека, сброс EQ, отсутствие выбранного имени под кругом, одновременная видимость двух статусов, потеря списка плейлистов при возврате.
- Временный harness текущей проверки: `/tmp/soundfield-peer-review.cjs`. Для долговременного воспроизведения сценарии описаны в R5–R11; исходный прототип идентифицирован SHA-256 выше.
- Это не end-to-end проверка браузера: DOM-заглушка не рассчитывает размеры и не воспроизводит захват pointer, прокрутку и системное распознавание жестов.
- Ручная проверка локальной страницы не выполнена. Ранее доступ к `file://` был отклонён механизмом доступа браузерного инструмента; обход этого ограничения не выполнялся.
