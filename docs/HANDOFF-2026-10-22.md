## 4. Правила продолжения (кратко)

1. **Версии:** любое изменение кода — подъём `versionName`/`versionCode` (`android/app/build.gradle.kts`), `MARKETING_VERSION`/`CURRENT_PROJECT_VERSION` (`ios/project.yml`, `ios/SoundField.xcodeproj/project.pbxproj`, при необходимости `tools/gen_xcodeproj.py`), `SFDSP_VERSION` (`dsp/include/sfdsp_version.h`) — и документация в том же наборе изменений.
2. **Git:** один законченный пункт — один коммит, `git add <пути>` (не `-A`); ветка этапа — от рабочей линии; доставка `git -C /Users/restart/Downloads/SoundField merge --ff-only <ветка>`; чужие незакоммиченные файлы в основном чекауте (`.DS_Store`, `Проектируем протокол обмена … LLMs sep26 15-26.txt`) не трогать.
3. **Распределение работы:** Sonnet — проектирование, алгоритмы ядра, проверка; Haiku 5.5 — механические части по точным заданиям с непересекающимися файлами и обязательными проверками; диффы агентов всегда проверяются ведущим по коду (за этот чат агенты дали минимум по одному дефекту в каждой волне).
4. **Документы UI главнее любого плана:** если пункт противоречит `docs/player-upper-controls.md`, пункт не делается.
