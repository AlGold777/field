# ТЗ: эквалайзер SoundField

База: Android 1.5.5 (`codex/audio-file-queue`). Целевая версия: **1.8.0** (номер 1.8.0 освободился — общая библиотека
отложена). Зависимость: соло-режим 1.6.0 (для работы без пары); от режима Amplifier (1.7.0) не зависит.
iOS — вне объёма; в паре с устройством без поддержки эквалайзер недоступен (п. 6.3).

## 1. Цель

Эквалайзер уровня лучших продуктов 2026 года, а не «10 ползунков». Что делает его таким:

| Свойство | Зачем |
|---|---|
| **Честная кривая**: на графике — реальная АЧХ фильтров, а не линия через точки ползунков | что видишь, то и слышишь |
| **Точность**: АЧХ проходит через значения ползунков с ошибкой ≤ 0,5 дБ | у обычного графического эквалайзера соседние полосы складываются, и +6 дБ на двух соседних дают +9 дБ между ними |
| **Магнитные ползунки**: тянешь одну полосу — соседние плавно следуют | кривая остаётся гладкой, музыкально правильной |
| **Анализатор спектра** под кривой, в реальном времени | видно, что в музыке происходит там, где крутишь |
| **Автозапас по уровню** | подъём полос не вызывает клиппинг |
| **Сравнение «с/без» при равной громкости** | иначе «громче» всегда кажется «лучше» |
| **Профили по устройству вывода**: динамик, проводные наушники, каждое Bluetooth-устройство | наушникам и динамику телефона нужны разные настройки |
| **Плавность**: изменения без щелчков и «молнии» (zipper noise) | можно крутить во время музыки |

## 2. Полосы

- **10 полос, октавная сетка ISO**: 31, 63, 125, 250, 500 Гц, 1, 2, 4, 8, 16 кГц. Диапазон ±12 дБ, шаг 0,5 дБ.
- Почему не больше: на экране 360 dp ползунок полосы — ≥ 32 dp шириной, это предел для пальца. Более точная
  подстройка делается перетаскиванием самой кривой (п. 4.3), а магнит (п. 4.2) даёт плавные переходы, которые на
  31-полосном эквалайзере пришлось бы выставлять вручную.
- DSP сделать для **N полос** (параметр), чтобы позже можно было включить 1/3 октавы (31 полосу) для планшетов
  и режима калибровки, не меняя обработку.

## 3. Обработка (DSP)

### 3.1 Точный каскадный графический эквалайзер
Метод — «accurate cascade graphic equalizer» (Välimäki & Liski, IEEE SPL 2017; обзор — Liski & Välimäki,
«The quest for the best graphic equalizer», DAFx 2017):
- на каждую полосу — пиковый (peaking) биквад на центральной частоте, добротность для октавной сетки
  (Q ≈ 1,41 как отправная точка; подобрать по статье);
- **усиления фильтров не равны значениям ползунков**: они вычисляются методом наименьших квадратов через матрицу
  взаимодействия полос, чтобы суммарная АЧХ проходила через значения ползунков. Итерация (обычно 1–2 прохода)
  при каждом изменении. Матрица зависит только от сетки — считается один раз;
- проверка точности (п. 9): на центральных частотах ошибка ≤ 0,5 дБ, между центрами — отклонение от гладкой
  интерполяции ≤ 1 дБ, для любых значений в ±12 дБ.

### 3.2 Где работает — на каждом устройстве, на выходе
- Эквалайзер **поканальный** (одинаковый фильтр для L и R), поэтому он может работать там, где звук выводится:
  на Server — для его канала(ов), на Point — для его. Так изменение слышно сразу, а не через 400 мс опережения,
  с которым Server отправляет аудио на Point.
- Граница с пространственным процессором (`docs/width-depth-synthesis.md`): тот **межканальный** и работает на
  Server до разделения каналов; эквалайзер — поканальный, на выходе каждого устройства. Будущее согласование тембра
  двух телефонов — отдельный слой перед пользовательским эквалайзером; пользовательский эквалайзер его не заменяет
  и не меняет. (Как время и уровень — независимые слои, `tz-balance-and-level.md` §3.)
- Место в цепочке рендера (`ServerRenderer`, `PointRenderer`, соло-рендер `Ch.BOTH`):
  `сэмпл → эквалайзер (с автозапасом) → громкость/баланс/подстройки уровня → GainRamp → ограничитель пиков → выход`.
  Фильтры работают по выходному потоку (после корректора), состояние фильтра — на канал.
- **Одинаковая задержка на всех устройствах.** Биквады минимально-фазовые, одинаковые на обоих телефонах — фазовые
  сдвиги одинаковы, L/R не расходятся. Ограничитель пиков имеет постоянное заглядывание вперёд (1 мс), которое
  **всегда включено** на всех устройствах, в том числе при выключенном эквалайзере, — иначе включение эквалайзера
  сдвинуло бы синхронизацию.
- Точка с плавающей запятой, двойная точность для состояний фильтров (на низких частотах одинарной не хватает).

### 3.3 Плавность
- Новые коэффициенты не подставляются скачком: интерполяция **параметров** (усиление, частота) за ~30 мс с
  пересчётом коэффициентов каждые 32 сэмпла, либо перекрёстное затухание двух наборов фильтров за 20 мс. Выбрать
  один способ, проверить тестом п. 9.4.
- Из UI во время перетаскивания — не чаще 60 обновлений в секунду.

### 3.4 Автозапас и защита от клиппинга
- **Автоматический предусилитель**: `preamp = −max(0, пик реальной АЧХ по 20 Гц – 20 кГц)`, пересчитывается при
  изменении, меняется плавно (п. 3.3). Показывается на экране («Запас −4,5 дБ»).
- **Ограничитель пиков** в конце цепочки (порог **0 dBFS**, заглядывание 1 мс, восстановление 50 мс) — последняя
  защита. Порог именно 0 dBFS: мастеринг музыки часто доходит до −0,1 dBFS, и более низкий порог поджимал бы пики
  даже без эквалайзера. При автозапасе и громкости ≤ 0 дБ он срабатывает только на редких межсэмпловых превышениях; счётчик срабатываний — в телеметрию. В приложении сейчас ограничителя нет вообще; он нужен и независимо
  от эквалайзера.
- Опция «Сохранять громкость» (по умолчанию вкл.): при автозапасе громкость музыки не должна проседать заметно —
  компенсация по средней громкости (оценка по взвешенной АЧХ, не по пику), но без выхода за 0 дБ.

### 3.5 Сравнение «с/без» при равной громкости
- Кнопка «Без эквалайзера» (удержание или переключатель): обход фильтров **с компенсацией громкости** — разница
  громкостей оценивается по АЧХ, взвешенной кривой громкости (K-взвешивание BS.1770) на розовом спектре; обход
  воспроизводится на ту же громкость. Переход — перекрёстное затухание 30 мс.

## 4. Взаимодействие

### 4.1 Экран
- Вход: в карточке Sound — строка «Эквалайзер» с мини-кривой справа и статусом («Выкл», «Вокал», «Свой»). Нажатие —
  полноэкранный `Sub.EQUALIZER`. Доступен в соло и в паре на обоих телефонах.
- Сверху — **график**: логарифмическая ось 20 Гц – 20 кГц, ±12 дБ, сетка 0 / ±6 / ±12 дБ, подписи частот полос.
  - Кривая — реальная АЧХ (п. 3.1), 256 точек по логарифму частоты, сглаженная линия акцентного цвета; заливка от 0 дБ
    к кривой полупрозрачным градиентом (выше нуля — тёплый, ниже — холодный оттенок).
  - Точки полос на кривой — перетаскиваемые узлы.
  - **Анализатор** за кривой: спектр того, что сейчас играет этот телефон, после эквалайзера; 1/6 октавы,
    ~30 кадров/с, быстрая атака и медленный спад (~300 мс), полупрозрачный. Выключается переключателем.
- Под графиком — **10 вертикальных ползунков, выровненных по тем же частотам, что и узлы графика**, со значением над
  ползунком во время перетаскивания.
- Ряд управления: «Магнит: Выкл / Мягко / Сильно», «Без эквалайзера» (п. 3.5), «Сброс», индикатор запаса.
- Ниже — пресеты (п. 5) горизонтальной лентой и «Сохранить как…».

### 4.2 Магнитные ползунки
- При начале перетаскивания полосы `i` запоминаются исходные значения всех полос `g0`.
- При смещении полосы `i` на `Δ` дБ соседние: `g_j = clamp(g0_j + Δ·w(d_ij), −12, +12)`, где
  `d_ij = |log2(f_j / f_i)|` — расстояние в октавах, `w(d) = exp(−ln2 · (d/σ)²)` (на расстоянии σ октав сосед
  проходит половину пути), `w(i) = 1`, при `w < 0,05` соседа не трогать.
- σ: «Мягко» = 0,8 октавы (соседи ±1 полоса заметно, ±2 — слегка), «Сильно» = 1,4 октавы. «Выкл» — полосы
  независимы.
- Сосед не может уйти дальше от нуля в сторону движения, чем тянущая полоса (не «перелетает» её).
- **Точный режим**: долгое нажатие на ползунок или узел — магнит временно выключен для этого перетаскивания
  (вибро-отклик при включении).
- Анимация: соседи двигаются вместе с пальцем без запаздывания (это не пружина, а мгновенное следование) —
  визуально «натянутая ткань».

### 4.3 Жесты на графике
- Перетаскивание узла по вертикали — как ползунок (с магнитом).
- Перетаскивание по пустой области графика — двигает ближайшую по частоте полосу (с магнитом): можно «рисовать»
  кривую пальцем, проводя вдоль графика (каждая полоса под пальцем принимает высоту пальца, магнит сглаживает).
- Двойное нажатие на узел или ползунок — полоса в 0 дБ (с магнитом соседи не трогаются).
- Вибро-отклик при прохождении 0 дБ; «липкость» у 0 дБ ±0,3 дБ.

### 4.4 Особенности динамика телефона
- При выводе на динамик телефона область ниже ~200 Гц на графике затенена с подписью «динамик телефона здесь почти
  не звучит». Подъём полос 31 и 63 Гц на этом выходе ограничен +3 дБ: он не даёт слышимого баса, но съедает запас
  (п. 3.4) и громкость всего остального.

## 5. Пресеты и профили

- Встроенные: «Ровно», «Больше баса», «Вокал», «Яркость», «Мягко», «Динамик телефона» (срез ниже 150 Гц, лёгкий
  подъём 1–4 кГц для разборчивости — освобождает запас на динамике). Значения пресетов — в одном файле-таблице,
  не разбросаны по коду; подобрать на слух, записать в README.
- Свои пресеты: сохранить / переименовать / удалить, хранятся на телефоне (как плейлисты).
- **Профили по выходу**: для каждого выхода (динамик, проводные наушники, каждое Bluetooth-устройство по имени)
  запоминается последняя настройка и включается автоматически при смене выхода; название выхода показано на экране
  («Для: Sony WH-1000XM6»).
- В паре: одна настройка на пару, её хранит Server (`PairRecord.eq`), изменения с любого телефона идут на Server.
  Профиль по выходу в паре не применяется (оба играют через динамики).

## 6. Синхронизация настроек в паре

### 6.1 Путь — как у громкости и баланса (переиспользовать)
- Команда `cmd a="eq"` с полями `{gains: [10 × дБ], enabled, magnet?, preset?, finished}` идёт тем же путём, что
  `vol` / `balance` (`sendGainCommand`, троттлинг промежуточных значений, `finished` — последнее значение).
- Server применяет у себя и публикует в `state` (`"eq": {...}`); Point применяет из `applyState`.
  Отдельный механизм не делать.
- Вычисленные коэффициенты **не передаются**: каждое устройство считает их само из значений полос одним и тем же
  кодом (детерминированно) — результат побитово одинаков.
- Одновременность: изменение на двух телефонах может разойтись на время доставки команды (единицы мс) — при
  сглаживании 30 мс это неслышно; отдельной привязки ко времени Server не нужно.

### 6.2 Соло
Настройка — из профиля текущего выхода (п. 5). Переход соло → пара: включается настройка пары; пара → соло —
настройка профиля выхода.

### 6.3 Совместимость
Capability `eq` в `localCapabilitiesJson()`. Если у второго телефона её нет — в паре эквалайзер выключен на обоих
(иначе каналы звучали бы по-разному), на экране: «Эквалайзер в паре требует SoundField 1.8.0 на обоих телефонах».

## 7. Производительность
- 10 биквадов × канал на 48 кГц — пренебрежимо; проверить на Redmi 14C: время рендера блока не растёт больше
  чем на 5 %, недоборов (`underruns`) не прибавляется.
- Анализатор: БПФ 4096 с шагом ~1600 сэмплов (30 кадров/с) — не в аудиопотоке: аудиопоток кладёт сэмплы в
  кольцевой буфер без блокировок, БПФ считает отдельный поток, только пока экран эквалайзера открыт.
- Решение наименьших квадратов (10×10) — при каждом изменении, в фоновом потоке движка, не в аудиопотоке;
  аудиопоток получает готовый неизменяемый снимок коэффициентов (как `ServerPlayState`).

## 8. Телеметрия
`EQ_CHANGE` {preset, gains, preampDb, magnet, by: server/point/solo, route} — только по `finished`;
`EQ_BYPASS` {on, loudnessCompDb}; `LIMITER_ACTIVE` {count, maxReductionDb} — раз в окно диагностики;
`EQ_ROUTE_PROFILE` {route, applied}.

## 9. Проверки (модульные тесты)
1. **Точность**: 1000 случайных наборов полос в ±12 дБ → АЧХ на центральных частотах отличается от значений ≤ 0,5 дБ;
   наборы «+12 на одной полосе», «чередование ±12», «все +12» — отдельно.
2. «Ровно» (все 0) на входе с пиками ≤ 0 dBFS → выход побитово равен входу, сдвинутому на постоянную задержку
   ограничителя (фильтры обходятся, ограничитель не срабатывает).
3. **Магнит**: σ и формула п. 4.2; соседи не перелетают тянущую полосу; `w < 0,05` → без изменений; «Выкл» —
   двигается только одна полоса.
4. **Плавность**: скачок полосы 0 → +12 дБ во время синуса 1 кГц — максимальный скачок между соседними сэмплами
   не больше, чем у самого синуса ×1,05; нет всплесков в спектре выше 5 кГц сильнее −80 дБ.
5. **Детерминизм**: два экземпляра с одинаковыми значениями на одинаковом входе → побитово одинаковый выход.
6. **Задержка**: импульс через цепочку с эквалайзером «Ровно» и «+6 на 1 кГц» — задержка ограничителя одинакова,
   эквалайзер не добавляет постоянной задержки.
7. **Автозапас**: «все +12» на розовом шуме 0 dBFS пик → ограничитель не срабатывает больше чем на 1 дБ.
8. **Сравнение**: разница громкости «с/без» по BS.1770 на розовом шуме ≤ 0,5 LU.

## 10. Приёмка (ручная)
1. Соло, наушники: «Больше баса», сравнить с «Без эквалайзера» — громкость одинакова, отличается только тембр.
2. Потянуть 1 кГц на +8 с магнитом «Мягко» — 500 Гц и 2 кГц поднимаются примерно наполовину, 250 и 4 кГц — слегка;
   кривая гладкая; на графике пик ровно +8.
3. Нарисовать кривую пальцем по графику — ползунки следуют.
4. Быстро крутить полосу во время музыки — без щелчков.
5. Все полосы +12 — нет искажений, индикатор запаса около −12 дБ, громкость не проваливается (п. 3.4).
6. Подключить BT-наушники → включилась их настройка; отключить → вернулась настройка динамика.
7. Пара: изменить эквалайзер на Point — слышно на обоих телефонах одновременно; синхронизация L/R (индикатор и
   `sync_probe` из spatial-proto) не хуже, чем без эквалайзера.
8. Пара с телефоном без capability `eq` — эквалайзер недоступен, подсказка.
9. Redmi 14C: 30 мин с открытым экраном эквалайзера и анализатором — без недоборов и перегрева.
