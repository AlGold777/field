# ТЗ: плеер на главном экране (соло-режим без пары)

База: Android 1.5.5, ветка `codex/audio-file-queue`. Целевая версия: **1.6.0** (новая функциональность).
iOS — вне объёма этого ТЗ (отдельный этап после проверки на Android).

## 1. Проблема

Сейчас плеер существует только внутри пары:

- `MainActivity.AppRoot`: `!ui.inPair -> WelcomeScreen`, `PlayerScreen` показывается только при `PAIRED/RECONNECTING`.
- `Engine.cmd()` отбрасывает любую команду без пары (`if (!ui.value.inPair) return@post`).
- `Engine.addAudioFiles()` и `requestTrackPicker()` без пары отвечают «Сначала подключите второй телефон».
- `Engine.selectTrack()` выходит, если `phase` не `PAIRED/RECONNECTING`.
- `goIdle()` останавливает `AudioOutput`, снимает `PlaybackService` и аудиофокус.
- `ServerRenderer` выдаёт **один канал** (`st.channel`), `AudioOutput` открывает `AudioTrack` как `CHANNEL_OUT_MONO`.

Итог: одним телефоном нельзя просто слушать музыку (в наушниках, на колонке по BT, на самом телефоне), хотя очередь, декодер, плейлисты и управление уже есть.

## 2. Цель

Главный экран приложения — **плеер**. Он работает сразу, без второго телефона, в полном стерео. Стереопара — это
надстройка: подключили второй телефон — та же музыка без остановки разошлась на L/R; разорвали пару — музыка
продолжает играть в стерео на этом телефоне.

## 3. Модель состояний

Добавить понятие **локального воспроизведения** (соло). Отдельную `Phase` не вводить: соло = `Phase.IDLE`
+ телефон ведёт себя как Server без Point.

| Состояние | Кто владеет очередью | Что звучит на этом телефоне |
|---|---|---|
| IDLE (соло) | этот телефон | оба канала (стерео) |
| PAIRED/RECONNECTING, роль Server | этот телефон | свой канал пары (как сейчас) |
| PAIRED/RECONNECTING, роль Point | второй телефон (Server) | свой канал пары (как сейчас) |

В `UiState` добавить вычисляемое `val solo: Boolean get() = phase == Phase.IDLE` (или эквивалент) и использовать его в UI.
Для телеметрии роль в соло — `"solo"` (поле `role` в `USER_COMMAND`, `USER_MARK`, экспорт).

## 4. Движок (Android)

### 4.1 Команды и очередь без пары

Переиспользовать существующий путь Server — не делать параллельный плеер.

- `cmd()`: без пары выполнять `handleCmd(o)` локально (как Server). Условие `!inPair → return` заменить на:
  соло или `role == SERVER` → `handleCmd`; `role == POINT` → отправка по `link` (как сейчас).
  Проверить `handleCmd` на обращения к `link`/Point (отправка `timeline`, `state`, `queue`) — в соло они должны
  становиться no-op, а не падать и не писать «Нет связи».
- `requestTrackPicker()`, `addAudioFiles()`: в соло работать как у Server.
- `selectTrack()`: допускать `Phase.IDLE`.
- Плейлисты (`savePlaylist/openPlaylist`): в соло доступны (проверка `role == SERVER` → «соло или Server»).
- `positionMs()`: в соло — ветка Server.
- В соло переменная `role` должна быть `Role.SERVER` (или все проверки `role == Role.SERVER` в путях плеера
  расширены на соло — выбрать один способ и применить единообразно; предпочтительно первый, меньше правок).
  Важно: после выхода из пары в роли Point `role` нужно вернуть в `SERVER`.

### 4.2 Стерео-вывод

- Соло: `AudioTrack` в `CHANNEL_OUT_STEREO`, рендер выдаёт интерлив L/R: `src.sample(f, Ch.L)`, `src.sample(f, Ch.R)`.
  Корректор (`PlayoutCorrector`), envelope, `GainRamp`, учёт `SegmentedPcmSource.readyFrames` — те же, что в `ServerRenderer`.
  Рекомендуемый вариант: параметр `channel` в `ServerPlayState` расширить значением «оба» (например `Ch.BOTH = -1`),
  и `ServerRenderer` при нём пишет стерео-кадр. Не копировать рендерер.
- Пара: вывод **остаётся моно, как сейчас**. Не менять формат `AudioTrack` в паре — от него зависят замеры
  задержки и сохранённая калибровка (`trimMs`, `delayCalib`).
- `AudioOutput` должен уметь переоткрыть трек с другим числом каналов. Переход моно ↔ стерео — только в моменты
  создания/разрыва пары (п. 5), с короткой рампой вниз/вверх (`GainRamp`), без щелчка. Пауза до ~150 мс допустима.
- Громкость в соло: `master` по тому же закону (`AudioGain`). Баланс в соло — между L и R этого телефона по тому же
  `BalanceLaw`. Подстройки уровня пары (`levelTrimServerDb/PointDb`) и `trimNs` в соло **не применяются**.

### 4.3 Фон, фокус, уведомление

- Когда в соло идёт воспроизведение — запускать `PlaybackService` (иначе Android заморозит процесс в фоне).
  Уведомление в соло: заголовок «SoundField», текст «играет/пауза — <трек>». Когда соло на паузе дольше 5 мин
  или очередь пуста — сервис можно снять (как у обычных плееров).
- Аудиофокус: в соло тот же `requestFocus()/abandonFocus()`. При `AUDIOFOCUS_LOSS*` — пауза с текстом без слова
  «пара» («Звук прерван (звонок или другое приложение)»).
- Добавить обработку `ACTION_AUDIO_BECOMING_NOISY` (отключили наушники/BT) → пауза. Сейчас её нет; в соло с
  наушниками без неё музыка внезапно пойдёт в динамик. В паре поведение то же (пауза всей пары) — это ожидаемо.
- `onBackground()/hideWhileBackground()`: снятие mDNS-публикации в фоне без пары оставить, но оно **не должно**
  затрагивать воспроизведение. Если в соло играет и работает `PlaybackService`, публикацию можно не снимать
  (процесс жив) — это позволит второму телефону найти нас, пока мы слушаем музыку в фоне.

## 5. Переходы соло ↔ пара

### 5.1 Этот телефон становится Server (пригласили мы / восстановление с ролью Server)
- Очередь, текущий трек, позиция и состояние play/pause **сохраняются**. Ветка `!continuing` в установке пары сейчас
  делает `newEpoch(false, 0, …)` — это обнуляет позицию и ставит паузу. Для перехода из соло нужно стартовать
  эпоху с текущей позиции и текущего `playing`, затем `sendSession/sendTimeline/publishState/publishQueue` как сейчас.
- Вывод: стерео → моно своего канала (п. 4.2). Point догоняет с текущего места стандартным механизмом.

### 5.2 Этот телефон становится Point (приняли приглашение / восстановление с ролью Point)
- Локальное воспроизведение ставится на паузу, **локальная очередь сохраняется в памяти** (не удалять
  декодированные файлы текущего и соседних треков). На экране — очередь Server, как сейчас.
- Диалог входящего приглашения, если в соло играет музыка, дополнить строкой: «Музыка на этом телефоне будет
  остановлена». Кнопки прежние.

### 5.3 Разрыв пары (`goIdle`)
- Бывший Server: воспроизведение **не останавливается**; вывод моно → стерео, та же позиция. `audio.stop()`,
  `abandonFocus()`, `PlaybackService.stop()` в `goIdle` выполнять только если соло не играет.
  Сейчас `goIdle` делает `serverPlay = ServerPlayState(Timeline.NONE, …)` — в соло-переходе вместо этого сохранить
  таймлайн и переключить канал на «оба».
- Бывший Point: возвращается к своей сохранённой локальной очереди на паузе (позиция, на которой встал в п. 5.2).
- Потеря связи (`RECONNECTING`) — без изменений: это всё ещё пара.

### 5.4 Автовосстановление пары во время соло
- Если сохранённая роль этого телефона — **Server**: восстанавливать как сейчас (музыка не прерывается, п. 5.1).
- Если сохранённая роль — **Point** и в соло идёт воспроизведение: **не восстанавливать молча** (иначе музыка
  оборвётся сама по себе). Показать на главном экране строку ««<имя>» рядом — подключить?» с кнопкой; нажатие
  выполняет `resumeRemembered()`. Если соло на паузе — автовосстановление как сейчас.
- Входящий `resume` от второго телефона при роли Point и играющем соло — тоже не принимать молча: ответ как у
  «занятого» телефона (`busy`) + та же строка-предложение. Проверить, что Server корректно продолжает попытки.

## 6. UI (Android)

### 6.1 Навигация
- `AppRoot`: убрать ветку `!ui.inPair -> WelcomeScreen`. Корневой экран всегда `PlayerScreen`.
- Строка `if (!ui.inPair && sub != …) sub = Sub.NONE` — пересмотреть: «Диагностика» доступна и в соло;
  «Калибровка» — только в паре (при разрыве пары, если открыта калибровка, вернуть на плеер).
- Добавить `Sub.PAIRING` — экран подключения второго телефона. Содержимое — нынешний `WelcomeScreen` без логотипа
  и без `TelemetryButton` (она уже есть на плеере): «Знакомая пара», «Телефоны рядом», «Журнал подключения».
  После успешной пары экран закрывается сам. Назад → плеер.
- Диалоги `INVITING` и `INCOMING` перенести из `WelcomeScreen` в `AppRoot`, чтобы входящее приглашение
  появлялось поверх плеера на любом экране.

### 6.2 Плеер в соло
- Вместо `PairStatusButton` — кнопка «Подключить второй телефон» (открывает `Sub.PAIRING`). Если есть знакомая
  пара — рядом/вторым действием «Подключить «<имя>»» (`resumeRemembered()`). Бейдж SERVER/POINT в соло не показывать.
- Стереосцена: в соло один круг «Этот телефон · L+R» (или два круга L и R, оба помечены «Этот телефон»; без
  переключения каналов по тапу). Предпочтительно один круг — проще и честнее.
- Индикатор синхронизации L/R, предупреждение `multiWifiWarning`, `audioMissing` — в соло скрыть.
- Подсказка под названием трека в соло: «Нажмите на название, чтобы добавить FLAC, WAV или MP3».
- Карточка Sound: «Громкость» как есть; «Баланс между телефонами» → в соло «Баланс L/R».
- Нижний ряд: в соло «Калибровка» скрыта (или неактивна), «Диагностика» и телеметрия остаются.
- Пустая очередь в соло: крупная кнопка «Добавить музыку» по центру вместо «—» в названии трека.

### 6.3 Плеер в паре
Без изменений, кроме того, что `PairStatusButton` теперь также ведёт себя как сейчас (разрыв пары с подтверждением).

## 7. Что не меняется
- Протокол, форматы TCP/UDP, логика переподключения и диагностики LAN — без изменений (кроме ответа `busy` в п. 5.4,
  который уже есть в протоколе).
- Калибровка задержки и уровня — только в паре; её данные в соло не используются и не сбрасываются.
- Очередь между перезапусками приложения по-прежнему не сохраняется (плейлисты — сохраняются). Это отдельная задача.

## 8. Телеметрия
- `SOLO_PLAYBACK_START` / `SOLO_PLAYBACK_STOP` (reason: user / focus / noisy / pair).
- `SOLO_TO_PAIR` {asRole, wasPlaying, positionMs, gapMs} и `PAIR_TO_SOLO` {fromRole, resumedPlaying, positionMs, gapMs}.
  `gapMs` — фактическая тишина при переоткрытии `AudioTrack`.
- `AUTO_RESUME_DEFERRED` {reason: "solo_playing_as_point"} для п. 5.4.
- `AUDIO_BECOMING_NOISY` {phase, role}.

## 10. Приёмка (ручной чек-лист)
1. Холодный старт без пары → сразу плеер. Добавить файлы → играет **стерео** в наушниках (проверить тестовым
   файлом с разным сигналом в L и R).
2. Соло играет → свернуть приложение, заблокировать экран на 10 мин → музыка идёт, уведомление есть, управление с
   экрана блокировки работает.
3. Отключить наушники во время соло → пауза, звук не пошёл в динамик.
4. Звонок во время соло → пауза.
5. Соло играет на A → с A пригласить B → A стал Server, музыка **не остановилась и не перемоталась**, B подхватил
   с текущего места. Зазор на A ≤ 150 мс.
6. Соло играет на B → A приглашает B → на B в диалоге предупреждение; после «Принять» B — Point, играет пару A.
   Разорвать пару → на B своя очередь на той же позиции, на паузе; на A музыка продолжается в стерео.
7. Разрыв пары с Server во время воспроизведения → музыка продолжается в стерео без перемотки.
8. Знакомая пара, где этот телефон Point, соло играет → второй телефон появился → музыка **не прервалась**,
   показано предложение подключиться; нажатие — подключает.
9. Входящее приглашение, пока открыт экран Диагностики в соло → диалог виден.
10. Калибровка в паре работает как раньше, сохранённый `trimMs` не изменился после цикла соло → пара → соло.
