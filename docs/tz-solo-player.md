# ТЗ: плеер на главном экране, режим Amplifier, общая библиотека

База: Android 1.5.5, ветка `codex/audio-file-queue`. iOS — вне объёма (отдельный этап после проверки на Android).

Три этапа, каждый — отдельная версия, отдельные коммиты и отдельная проверка на телефонах:

| Этап | Версия | Что |
|---|---|---|
| 1 | 1.6.0 | Соло-плеер на главном экране, стерео без пары, переходы соло ↔ пара без остановки |
| 2 | 1.7.0 | Переключатель режима пары **Stereo / Amplifier** |
| 3 | 1.8.0 | Общая библиотека: очереди и плейлисты обоих телефонов для совместного выбора |

Этап 2 опирается на стерео-вывод из этапа 1 (п. 1.4.2), этап 3 — на сохранение очереди Point из этапа 1 (п. 1.5.2).

# Этап 1. Соло-плеер (1.6.0)

## 1.1 Проблема

Сейчас плеер существует только внутри пары:

- `MainActivity.AppRoot`: `!ui.inPair -> WelcomeScreen`, `PlayerScreen` показывается только при `PAIRED/RECONNECTING`.
- `Engine.cmd()` отбрасывает любую команду без пары (`if (!ui.value.inPair) return@post`).
- `Engine.addAudioFiles()` и `requestTrackPicker()` без пары отвечают «Сначала подключите второй телефон».
- `Engine.selectTrack()` выходит, если `phase` не `PAIRED/RECONNECTING`.
- `goIdle()` останавливает `AudioOutput`, снимает `PlaybackService` и аудиофокус.
- `ServerRenderer` выдаёт **один канал** (`st.channel`), `AudioOutput` открывает `AudioTrack` как `CHANNEL_OUT_MONO`.

Итог: одним телефоном нельзя просто слушать музыку (в наушниках, по BT, на самом телефоне), хотя очередь,
декодер, плейлисты и управление уже есть.

## 1.2 Цель

Главный экран — **плеер**. Он работает сразу, без второго телефона, в полном стерео. Стереопара — надстройка:
подключили второй телефон — та же музыка без остановки разошлась на два телефона; разорвали пару — музыка
продолжает играть в стерео на этом телефоне.

## 1.3 Модель состояний

Отдельную `Phase` не вводить: соло = `Phase.IDLE` + телефон ведёт себя как Server без Point.

| Состояние | Кто владеет очередью | Что звучит на этом телефоне |
|---|---|---|
| IDLE (соло) | этот телефон | L и R (стерео) |
| PAIRED/RECONNECTING, роль Server | этот телефон | по режиму пары (этап 2), в 1.6.0 — свой канал |
| PAIRED/RECONNECTING, роль Point | второй телефон (Server) | по режиму пары (этап 2), в 1.6.0 — свой канал |

В `UiState` добавить `val solo: Boolean get() = phase == Phase.IDLE` и использовать его в UI.
Для телеметрии роль в соло — `"solo"` (поле `role` в `USER_COMMAND`, `USER_MARK`, экспорт).

## 1.4 Движок

### 1.4.1 Команды и очередь без пары

Переиспользовать существующий путь Server — не делать параллельный плеер.

- `cmd()`: в соло выполнять `handleCmd(o)` локально. Условие `!inPair → return` заменить на:
  соло или `role == SERVER` → `handleCmd`; `role == POINT` → отправка по `link` (как сейчас).
  Проверить `handleCmd` и `publishState/publishQueue/sendTimeline` на обращения к `link` — в соло это no-op,
  без тостов «Нет связи».
- `requestTrackPicker()`, `addAudioFiles()`, `selectTrack()`, плейлисты (`save/open/rename/delete`),
  `positionMs()` — в соло работают как у Server.
- В соло переменная `role = Role.SERVER` (меньше правок, чем расширять каждую проверку). После выхода из пары
  в роли Point вернуть `role = SERVER`.

### 1.4.2 Вывод звука — всегда стерео

- `AudioOutput` открывает `AudioTrack` **всегда** в `CHANNEL_OUT_STEREO`, в соло и в паре. Так не нужно
  переоткрывать трек при переходах соло ↔ пара (нет зазора), и этап 2 (Amplifier) получает стерео-вывод готовым.
- `RenderSource.render` пишет интерлив L/R. `ServerPlayState.channel` расширить значением `Ch.BOTH`:
  - `Ch.BOTH` → кадр `(sample(f, L), sample(f, R))`;
  - `Ch.L`/`Ch.R` (пара, Stereo) → свой канал в оба выхода (как сейчас звучит моно-трек).
  Корректор, envelope, `GainRamp`, учёт `SegmentedPcmSource.readyFrames` — общие, рендерер не копировать.
- `PointRenderer` в режиме Stereo пишет свой канал в оба выхода.
- Риск: смена формата трека может сдвинуть выходную задержку и сохранённую калибровку (`trimMs`, `delayCalib`).
  Логировать `outputLatency` до/после в телеметрию; в приёмке — п. 1.9, пункт 10.
- Громкость в соло — `master` по `AudioGain`. Баланс в соло — между L и R этого телефона по `BalanceLaw`.
  Подстройки уровня пары (`levelTrimServerDb/PointDb`) и `trimNs` в соло не применяются и не сбрасываются.

### 1.4.3 Фон, фокус, уведомление

- В соло во время воспроизведения запускать `PlaybackService`. Уведомление: «SoundField», «играет/пауза — <трек>».
  Соло на паузе дольше 5 мин или пустая очередь → сервис снять.
- Аудиофокус в соло — тот же `requestFocus()/abandonFocus()`. При `AUDIOFOCUS_LOSS*` — пауза с текстом без слова
  «пара».
- Добавить `ACTION_AUDIO_BECOMING_NOISY` (отключили наушники/BT) → пауза. Сейчас её нет; без неё музыка пойдёт в
  динамик. В паре — пауза всей пары.
- `hideWhileBackground()`: если в соло играет и работает `PlaybackService`, mDNS-публикацию не снимать
  (процесс жив, второй телефон может нас найти). Иначе — как сейчас.

## 1.5 Переходы соло ↔ пара

### 1.5.1 Этот телефон становится Server
- Очередь, трек, позиция и play/pause **сохраняются**. Ветка `!continuing` сейчас делает `newEpoch(false, 0, …)`
  (пауза + начало трека) — для перехода из соло стартовать эпоху с текущей позиции и текущего `playing`,
  затем `sendSession/sendTimeline/publishState/publishQueue` как сейчас.
- Вывод: `Ch.BOTH` → свой канал (с `GainRamp`). Point догоняет с текущего места стандартным механизмом.

### 1.5.2 Этот телефон становится Point
- Локальное воспроизведение → пауза. **Локальная очередь, индекс и позиция сохраняются** (в памяти; декодированные
  файлы текущего и соседних треков не удалять). На экране — очередь Server, как сейчас. Сохранённая очередь нужна
  этапу 3.
- Диалог входящего приглашения при играющем соло дополнить: «Музыка на этом телефоне будет остановлена».

### 1.5.3 Разрыв пары (`goIdle`)
- Бывший Server: воспроизведение **продолжается**, свой канал → `Ch.BOTH`, та же позиция. `audio.stop()`,
  `abandonFocus()`, `PlaybackService.stop()` — только если соло не играет. Вместо
  `serverPlay = ServerPlayState(Timeline.NONE, …)` сохранить таймлайн.
- Бывший Point: возвращается к своей сохранённой очереди на паузе.
- `RECONNECTING` — без изменений: это всё ещё пара.

### 1.5.4 Автовосстановление пары во время соло
- Сохранённая роль этого телефона **Server** → восстанавливать как сейчас (музыка не прерывается).
- Сохранённая роль **Point** и соло играет → не восстанавливать молча. Показать строку ««<имя>» рядом —
  подключить?» с кнопкой → `resumeRemembered()`. Соло на паузе → как сейчас.
- Входящий `resume` при роли Point и играющем соло → ответ `busy` + та же строка-предложение.
  Проверить, что Server продолжает попытки и подключится после нажатия.

## 1.6 UI

### 1.6.1 Навигация
- `AppRoot`: убрать ветку `!ui.inPair -> WelcomeScreen`; корневой экран всегда `PlayerScreen`.
- `if (!ui.inPair && sub != …) sub = Sub.NONE` пересмотреть: «Диагностика» доступна в соло; «Калибровка» —
  только в паре (разрыв пары при открытой калибровке → на плеер).
- Добавить `Sub.PAIRING` — экран подключения. Содержимое — нынешний `WelcomeScreen` без логотипа и без
  `TelemetryButton`: «Знакомая пара», «Телефоны рядом», «Журнал подключения». После успешной пары закрывается сам.
- Диалоги `INVITING` и `INCOMING` перенести из `WelcomeScreen` в `AppRoot` — видны поверх любого экрана.

### 1.6.2 Плеер в соло
- Вместо `PairStatusButton` — «Подключить второй телефон» (→ `Sub.PAIRING`); при знакомой паре — второе действие
  «Подключить «<имя>»» (`resumeRemembered()`). Бейдж SERVER/POINT не показывать.
- Стереосцена: **два круга L и R, как в паре; под обоими подпись «Этот телефон»**, строку роли (Server/Point)
  не показывать. Полоска между кругами и тап по кругам в соло не меняют каналы (нечего менять местами).
- Индикатор синхронизации L/R, `multiWifiWarning`, `audioMissing` — скрыты.
- Подсказка под названием трека: «Нажмите на название, чтобы добавить FLAC, WAV или MP3».
- Карточка Sound: «Баланс между телефонами» → «Баланс L/R».
- Нижний ряд: «Калибровка» скрыта; «Диагностика» и телеметрия остаются.
- Пустая очередь: крупная кнопка «Добавить музыку» по центру.

## 1.7 Не меняется
Протокол, переподключение, диагностика LAN; калибровка — только в паре; очередь между перезапусками по-прежнему
не сохраняется (плейлисты сохраняются) — отдельная задача.

## 1.8 Телеметрия
`SOLO_PLAYBACK_START/STOP` {reason: user/focus/noisy/pair}; `SOLO_TO_PAIR` {asRole, wasPlaying, positionMs, gapMs};
`PAIR_TO_SOLO` {fromRole, resumedPlaying, positionMs, gapMs}; `AUTO_RESUME_DEFERRED` {reason: "solo_playing_as_point"};
`AUDIO_BECOMING_NOISY` {phase, role}; `AUDIO_OUTPUT_FORMAT` {channels, outputLatencyMs}.

## 1.9 Приёмка
1. Холодный старт без пары → сразу плеер. Добавить файлы → играет **стерео** (тестовый файл с разным сигналом в L и R).
2. Соло играет → свернуть, заблокировать на 10 мин → музыка идёт, уведомление и управление с экрана блокировки работают.
3. Отключить наушники → пауза, звук не пошёл в динамик.
4. Звонок → пауза.
5. Соло на A → A приглашает B → A стал Server, музыка не остановилась и не перемоталась, B подхватил с текущего места.
6. Соло на B → A приглашает B → в диалоге предупреждение; после «Принять» B — Point. Разрыв пары → на B своя
   очередь на той же позиции на паузе; на A музыка продолжается в стерео.
7. Разрыв пары с Server во время воспроизведения → стерео без перемотки.
8. Знакомая пара, этот телефон Point, соло играет → второй телефон появился → музыка не прервалась, есть предложение подключиться.
9. Входящее приглашение, пока открыта Диагностика в соло → диалог виден.
10. После перехода на стерео-трек: «Проверка центра» в паре на откалиброванной паре звучит по центру; если сдвиг
    заметен — зафиксировать в телеметрии `outputLatency` и сообщить (решим: перекалибровка или компенсация).

# Этап 2. Режим пары Stereo / Amplifier (1.7.0)

## 2.1 Суть

| Режим | Server | Point |
|---|---|---|
| **Stereo** (как сейчас) | свой канал | свой канал |
| **Amplifier** | L и R | L и R — второй телефон работает как дополнительный динамик/усилитель |

Синхронизация, калибровка задержки, громкость и баланс между телефонами работают в обоих режимах одинаково.

## 2.2 UI
- Кнопка-переключатель **Stereo / Amplifier** на стереосцене: между кругами, **на уровне строки ролей**
  (Server/Point) под кругами — под полоской смены каналов. Сегментированная пилюля из двух значений, активное
  подсвечено `SFColors.accent`. Видна только в паре; в соло не показывается.
- Переключать может любой телефон пары (команда идёт на Server, как остальные `cmd`).
- В Amplifier: на обоих кругах подпись канала «L R» вместо «L»/«R»; полоска смены каналов неактивна (приглушена),
  тап по кругам не меняет каналы. «Баланс между телефонами» остаётся — это громкость телефонов относительно друг друга.
- Если второй телефон не поддерживает режим (нет capability `stereoAudio`, п. 2.3) — кнопка неактивна, по тапу
  тост «Режим Amplifier требует SoundField 1.7.0 на обоих телефонах».
- Калибровка в Amplifier: калибровка задержки и уровня доступны; «Проверка каналов» и «Проверка центра» —
  неактивны с подсказкой «Доступно в режиме Stereo».

## 2.3 Протокол
- Новая capability `stereoAudio` в `localCapabilitiesJson()`; режим Amplifier разрешён, только если она есть в
  `negotiatedCapabilities`.
- Режим хранит Server в `PairRecord.pairMode` (`"stereo"`/`"amp"`, по умолчанию `"stereo"`), передаёт в `state`
  (`"pairMode"`). Команда `cmd a="pairMode" mode=...`.
- UDP AUDIO: флаг в поле `flags` — бит `STEREO` (`0x08` или первый свободный — проверить занятые). При нём
  `count` — число **кадров**, за заголовком `count × 2 × i16` интерлив L/R. Чтобы пакет не превышал MTU
  (сейчас 480 кадров × 2 Б = 960 Б; стерео было бы 1920 Б → фрагментация), в Amplifier `PACKET_FRAMES` = 240
  (5 мс, 960 Б). Приёмник проверяет длину с учётом флага.
- TCP-аудио (`TcpAudio`): тот же признак стерео в чанке (новый тип кадра или поле каналов); `CHUNK_FRAMES` и
  `MAX_CHUNK_BYTES` пересчитать так, чтобы чанк по-прежнему покрывал 100 мс.
- `PointReceiver` и `TcpAudioBuffer` хранят кадры с числом каналов текущей эпохи; `read()` возвращает кадр.
- Старый Point без `stereoAudio` никогда не получает стерео-пакетов.

## 2.4 Переключение во время воспроизведения
- Server при смене режима начинает **новую эпоху с текущей позиции** (как при seek): Point сбрасывает буфер и
  набирает его заново в новом формате. Короткая пауза на Point допустима (как при перемотке); на Server — только
  рампа `GainRamp` при смене канала на `Ch.BOTH`.
- Разрыв пары в Amplifier → соло (`Ch.BOTH`), как в этапе 1. Режим запоминается для пары.

## 2.5 Телеметрия
`PAIR_MODE_CHANGE` {from, to, by: server/point, playing, positionMs, pointRefillMs}. В диагностике (`Diag`) — текущий
режим и пакетов/с.

## 2.6 Приёмка
1. Stereo → Amplifier во время игры: оба телефона звучат L+R (проверка тестовым файлом с разным сигналом в каналах),
   синхронно, без перемотки; зазор на Point ≤ 300 мс.
2. Amplifier → Stereo: каналы разошлись обратно по сохранённому назначению.
3. Переключение с Point работает.
4. Amplifier 30 мин с экраном выключенным на обоих: потери и `audioMissing` не хуже, чем в Stereo.
5. Переход на TCP-аудио (`POINT_BUFFER_LOW`) в Amplifier: звук остаётся стерео.
6. Пара с телефоном 1.6.0: кнопка неактивна, подсказка показана.
7. Разрыв пары в Amplifier → на бывшем Server стерео продолжается.

# Этап 3. Общая библиотека (1.8.0)

## 3.1 Проблема
После этапа 1 у каждого телефона своя очередь и свои плейлисты. В паре играет очередь Server, а очередь и
плейлисты Point недоступны (иконка «Плейлисты» на Point выключена: «Плейлисты хранятся на телефоне Server»).
Выбрать вместе, что слушать, нельзя.

## 3.2 UI
- В заголовке очереди (`QueueCard`) **перед** существующими иконками («Добавить музыку», «Выбрать треки»,
  «Плейлисты») — новая иконка **«Общая библиотека»** (Material `Sync` / `LibraryAdd`). Видна только в паре, на обоих
  телефонах.
- По тапу — лист «Общая библиотека», два раздела:
  - **«<Этот телефон>»**: его текущая очередь (для Point — сохранённая соло-очередь, п. 1.5.2) и его плейлисты;
  - **«<Имя второго>»**: то же для второго телефона.
- Для каждого элемента: «Заменить очередь» / «Добавить в конец» (как в существующем диалоге плейлиста).
  Действие меняет **общую** очередь пары (очередь Server), независимо от того, с какого телефона нажато.
- Элементы с Point показывают размер: «12 треков · 410 МБ · будут переданы на Server».

## 3.3 Движок и протокол
- Новое TCP-сообщение `library` (Point → Server по запросу и при изменении, Server → Point): список
  `{source: "queue"|"playlist", id, name, count, bytes?}`. Состав треков — по запросу `library-items {id}`,
  частями, как `queue`.
- Выбор элемента Server: `doOpenPlaylist`/текущая логика очереди, без изменений.
- Выбор элемента Point: файлы есть только на Point → **переиспользовать существующую передачу Point → Server**
  (`beginPointFileTransfer`), не делать второй механизм. Порядок треков сохраняется; треки появляются в очереди по
  мере прихода; при «Заменить очередь» воспроизведение первого трека начинается, когда он передан. Отмена —
  существующей кнопкой «Отменить передачу».
- Передача доступна только Android ↔ Android (как сейчас); иначе раздел Point показывается, но выбор неактивен
  с той же подсказкой, что и у отправки файлов.
- Файлы, уже переданные ранее (совпадение имени + размера + длительности), повторно не передавать.
- Плейлисты Point **не копируются** на Server автоматически. Если после выбора пользователь сохраняет общую
  очередь как плейлист — он сохраняется на Server (как сейчас).

## 3.4 Телеметрия
`LIBRARY_OPEN` {role, localItems, peerItems}; `LIBRARY_PICK` {from: local/peer, source: queue/playlist, action: replace/append,
tracks, bytes}; для передачи — существующие события `FILE_TRANSFER_*`.

## 3.5 Приёмка
1. A и B играли каждый свою очередь соло, затем пара (A — Server). На обоих телефонах в «Общей библиотеке» видны обе очереди.
2. На A выбрать очередь B «Заменить» → файлы передаются, первый трек начинает играть после передачи, пара играет очередь B.
3. На B выбрать плейлист A «Добавить в конец» → добавлен без передачи файлов.
4. Разрыв пары → у B снова его собственная соло-очередь.
5. Пара Android + iOS: раздел второго телефона без выбора, с подсказкой.
