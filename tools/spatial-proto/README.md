# Офлайн-прототип ширины и глубины

Инструмент рендерит слепые WAV-варианты пространственной обработки. Он не подключается к сети и не меняет приложение SoundField. Все выходы имеют 48 кГц, 24 bit PCM, без тегов; названия показываются как кодовые имена файлов. Закрытый `key.json` храните отдельно от папки, которую передаёте слушателям.

## 1. Установка

Нужен Python 3.10 или новее. Создайте виртуальное окружение и установите зависимости:

```bash
cd tools/spatial-proto
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Установка пакетов требует уже подготовленного окружения Python или локального кэша пакетов. После установки рендер, анализ и сводка работают офлайн.

## 2. Подготовка музыки

Положите в отдельную папку **3–5 стереотреков джаза** в WAV или FLAC. Монофайлы отклоняются. Для сравнения полезны разные составы:

- небольшое трио с контрабасом по центру;
- группа с духовыми;
- вокальный джаз с голосом в центре.

Из каждого файла инструмент берёт 40 секунд. По умолчанию выбирается самый громкий участок по среднему LUFS коротких трёхсекундных окон с шагом 0,5 с. Чтобы задать начало вручную, укажите в `config.yaml` секунды по имени файла или имени без расширения:

```yaml
fragment_starts:
  trio.flac: 82.5
  singer: 114
```

Джаз — единственный музыкальный материал первого этапа. Плотный поп, оркестр и речь этим тестом не проверяются.

## 3. Рендер слепых треков

```bash
python render.py /путь/к/jazz --listener Анна
```

Результат появится в `out/<дата>/`:

- `tracks/` — только кодовые WAV-файлы для очереди SoundField;
- `key.json` — соответствие кодов вариантам и параметры; слушателям не показывать;
- `scores_Анна.csv` — пустой шаблон оценок;
- `metrics.json`, `report_files.md` и PNG — объективные метрики по файлам.

Для нескольких слушателей можно повторить `--listener` в одной команде, например `--listener Анна --listener Борис`. Файлы при одинаковом seed совпадают, а порядок прослушивания и CSV создаются отдельно для каждого человека. Для повторяемого рендера задайте `--seed 1234`.

В SoundField добавьте содержимое `tracks/` в очередь и воспроизводите по порядку, напечатанному для конкретного слушателя. Не открывайте `key.json` до окончания оценивания. Пара телефонов стоит на расстоянии 1,5–2 м; слушатель располагается посередине на равном расстоянии и держит голову неподвижно. Громкость для всего теста одна. Треки одного фрагмента можно переключать сколько угодно.

Оцените каждый код от 0 до 100: ширина, глубина, центр (фокус голоса/контрабаса), окраска (100 — окраски нет), естественность и общее предпочтение. Для отдельного повтора со смещением головы примерно на 10 см заполните `shifted_center`; комментарий свободный. Системные эквалайзеры и улучшатели звука отключите на обоих телефонах.

## 4. Измерительный плейлист и анализ записи

Синтетические розовый шум и щелчки автоматически обрабатываются для отчёта по файлам. Чтобы записать пару телефонов в точке прослушивания, создайте последовательный плейлист `pink_center` и `pink_stereo` для всех вариантов с паузами:

```bash
python render.py --measure
```

Запишите `out/<дата>/measure/measure.wav` любым системным плеером через SoundField. Положите телефон-записывающее устройство микрофоном вверх в точке слушателя; если доступна стереозапись, сохраните её в WAV. Затем выполните:

```bash
python analyze_recording.py /путь/к/записи.wav --measure-key out/<дата>/measure/key.json
```

Скрипт определяет сегменты по паузам, сравнивает АЧХ с записанным REF и создаёт `report_recording.md` и PNG. Межмикрофонная когерентность стереозаписи — только грубый ориентир ширины, телефонный микрофон не является измерительным.

## 5. Синхронизация пары

Создайте 10-минутный стереосигнал: чирп 1–6 кГц длительностью 20 мс сначала только в L, через 100 мс только в R; следующая пара начинается через секунду.

```bash
python render.py --sync-probe
```

Воспроизведите `out/<дата>/sync_probe.wav` через SoundField на паре телефонов и запишите микрофоном из точки прослушивания. Анализ:

```bash
python analyze_recording.py /путь/к/sync-записи.wav --sync
```

`report_sync.md` содержит оценку ppm часов записывающего устройства, медианный интервал L→R (включая постоянную геометрию) и разброс относительно медианы: σ, p95, максимум и график. Цель прототипа — p95 не более 50 мкс.

## 6. Сводка оценок

Заполните `scores_<слушатель>.csv`, не меняя названия колонок. После всех прослушиваний:

```bash
python score.py --key out/<дата>/key.json \
  --scores out/<дата>/scores_Анна.csv out/<дата>/scores_Борис.csv \
  --metrics out/<дата>/metrics.json
```

`score_report.md` раскрывает коды, показывает медиану и межквартильный размах. Слушатель исключается, если оценил естественность REF ниже 70 более чем в половине фрагментов. Вариант проваливается при снижении медианы центра или окраски более чем на 10 пунктов либо при отклонении моно-суммы больше 2 дБ в любой полосе 200 Гц–5 кГц. Успех — прирост медианы ширины или глубины минимум на 15 пунктов без провала.

## 7. Отдельная проверка XTC на одном телефоне

```bash
python render.py /путь/к/jazz --xtc
```

Файлы появятся в `out/<дата>/xtc/tracks/`, ключ — в `out/<дата>/xtc/key.json`, шаблон — в `out/<дата>/xtc/scores_xtc.csv`. Перед рендером измерьте расстояние между динамиками и при необходимости измените `xtc.speaker_spacing_m` в конфиге. Воспроизводите варианты на Xiaomi 14 Ultra в горизонтальном положении на расстоянии 0,4 и 0,6 м. Системные эффекты Dolby и «улучшение звука» отключите. Сначала запустите `channel_id` и проверьте ориентацию динамиков. Соло-режим SoundField для этой проверки не требуется: подойдёт системный плеер. Для каждого кода поставьте оценки по тем же атрибутам и заполните `outside_phone` значением «да» или «нет».

## 8. Что настраивается

Все параметры вариантов, полос, когерентности, лимитера и XTC лежат в `config.yaml`. Версия обработки — `PROTO_VERSION` в `render.py`; она записывается в ключи и отчёты. Перед передачей файлов слушателям оставьте `key.json` отдельно.

Модульные проверки DSP запускаются так:

```bash
python -m unittest discover -s tests -v
```
