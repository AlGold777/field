# Офлайн-прототип ширины и глубины

Инструмент версии `0.1.3` рендерит слепые WAV-варианты пространственной обработки. CLI работает офлайн; браузерный интерфейс связывает Mac и телефоны только через локальную сеть и не меняет приложение SoundField. Все выходы имеют 48 кГц, 24 bit PCM, без тегов; названия показываются как кодовые имена файлов. Закрытый `key.json` храните отдельно от папки, которую передаёте слушателям.

## 1. Установка

Нужен Python 3.10 или новее. Создайте виртуальное окружение и установите зависимости:

```bash
cd tools/spatial-proto
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Установка пакетов требует уже подготовленного окружения Python или локального кэша пакетов. После установки рендер, анализ и сводка работают офлайн.

### Локальный браузерный интерфейс

Запустите сервер из этой папки:

```bash
python ui.py
```

Он откроет страницу на Mac и напечатает адрес локальной сети для телефона. Оставьте терминал с сервером открытым. На Mac выберите папку с 3–5 WAV/FLAC-файлами, подтвердите наличие записи с жёсткой панорамой и нажмите «Сделать треки для теста». После рендера появятся прогресс, QR-код, ссылка для телефона и кнопка открытия папки `tracks` в Finder.

Телефон должен быть в той же локальной сети, что и Mac. Отсканируйте QR-код: страница телефона показывает слепые WAV-файлы для скачивания и бланк оценок. Добавьте скачанный WAV в SoundField через системное меню «Поделиться». Ползунки 0–100 заполняются на телефоне из точки прослушивания; сохранение создаёт обычный `scores_<слушатель>.csv` в папке запуска, совместимый с `score.py`. Ключ и варианты до сохранения оценок интерфейс не раскрывает.

Раздел «Замер синхронизации» создаёт и скачивает `sync_probe.wav`; после загрузки записи тот же `analyze_recording.py` строит отчёт. «Раскрыть результаты» становится доступна после сохранения оценок и вызывает `score.py`. В настройках можно менять `config.yaml`, сбрасывать отдельные поля или весь файл к значениям по умолчанию.

Остановите сервер сочетанием Ctrl+C. Порт можно задать вручную, например `python ui.py --port 8765`; `python ui.py --no-browser` не открывает вкладку автоматически.

## 2. Подготовка музыки

Положите в отдельную папку **3–5 стереотреков джаза** в WAV или FLAC. Монофайлы отклоняются. Среди треков обязательно должен быть хотя бы один джазовый трек конца 1950-х или 1960-х годов с жёстким разведением инструментов по каналам: это самый тяжёлый случай для защиты по разнице уровней (ILD). Защита не распознает раздельные источники, если оба края одновременно заняты похожим по спектру материалом. Для сравнения полезны разные составы:

- небольшое трио с контрабасом по центру;
- группа с духовыми;
- вокальный джаз с голосом в центре.

Из каждого файла инструмент берёт 40 секунд. По умолчанию выбирается самый громкий участок по среднему LUFS коротких трёхсекундных окон с шагом 0,5 с. Чтобы задать начало вручную, укажите в `config.yaml` секунды по имени файла или имени без расширения:

```yaml
fragment_starts:
  trio.flac: 82.5
  singer: 114
```

Джаз — единственный музыкальный материал первого этапа. Плотный поп, оркестр и речь этим тестом не проверяются.

## 3. Рендер слепых треков

```bash
python render.py /путь/к/jazz --listener Анна
```

Результат появится в `out/<дата>/`:

- `tracks/` — только кодовые WAV-файлы для очереди SoundField;
- `key.json` — соответствие кодов вариантам и параметры; слушателям не показывать;
- `scores_Анна.csv` — пустой шаблон оценок;
- `metrics.json`, `report_files.md` и PNG — объективные метрики по файлам.

Для нескольких слушателей можно повторить `--listener` в одной команде, например `--listener Анна --listener Борис`. Файлы при одинаковом seed совпадают, а порядок прослушивания и CSV создаются отдельно для каждого человека. Для повторяемого рендера задайте `--seed 1234`.

В SoundField добавьте содержимое `tracks/` в очередь и воспроизводите по порядку, напечатанному для конкретного слушателя. Не открывайте `key.json` до окончания оценивания. Пара телефонов стоит на расстоянии 1,5–2 м; слушатель располагается посередине на равном расстоянии и держит голову неподвижно. Громкость для всего теста одна. Треки одного фрагмента можно переключать сколько угодно.

Оцените каждый код от 0 до 100: ширина, глубина, центр (фокус голоса/контрабаса), окраска (100 — окраски нет), естественность и общее предпочтение. Для отдельного повтора со смещением головы примерно на 10 см заполните `shifted_center`; комментарий свободный. Системные эквалайзеры и улучшатели звука отключите на обоих телефонах.

## 4. Измерительный плейлист и анализ записи

Синтетические розовый шум, щелчки и `pan_hard` автоматически обрабатываются для отчёта по файлам. Чтобы записать пару телефонов в точке прослушивания, создайте последовательный плейлист `pink_center`, `pink_stereo` и `pan_hard` для всех вариантов с паузами. `pan_hard` — независимые сигналы: розовый шум с ФНЧ 2 кГц в L («рояль») и розовый шум с ФВЧ 1 кГц в R («тарелки»). Он нужен для замера и отчёта и не добавляется в музыкальные слепые треки.

```bash
python render.py --measure
```

Запишите `out/<дата>/measure/measure.wav` любым системным плеером через SoundField. Положите телефон-записывающее устройство микрофоном вверх в точке слушателя; если доступна стереозапись, сохраните её в WAV. Затем выполните:

```bash
python analyze_recording.py /путь/к/записи.wav --measure-key out/<дата>/measure/key.json
```

Скрипт определяет сегменты по паузам, сравнивает АЧХ с записанным REF и создаёт `report_recording.md` и PNG. Межмикрофонная когерентность стереозаписи — только грубый ориентир ширины, телефонный микрофон не является измерительным.

## 5. Синхронизация пары

Создайте 10-минутный стереосигнал: чирп 1–6 кГц длительностью 20 мс сначала только в L, через 100 мс только в R; следующая пара начинается через секунду.

```bash
python render.py --sync-probe
```

Воспроизведите `out/<дата>/sync_probe.wav` через SoundField на паре телефонов и запишите микрофоном из точки прослушивания. Анализ:

```bash
python analyze_recording.py /путь/к/sync-записи.wav --sync
```

`report_sync.md` содержит оценку ppm часов записывающего устройства, медианный интервал L→R (включая постоянную геометрию) и разброс относительно медианы: σ, p95, максимум и график. Цель прототипа — p95 не более 50 мкс. Приёмочная симуляция добавляет дрейф записывающих часов ±20 ppm, разные АЧХ динамиков, разные комнатные импульсные характеристики с RT60 около 0,4 с и шум −40 дБ относительно чирпа.

## 6. Сводка оценок

Заполните `scores_<слушатель>.csv`, не меняя названия колонок. После всех прослушиваний:

```bash
python score.py --key out/<дата>/key.json \
  --scores out/<дата>/scores_Анна.csv out/<дата>/scores_Борис.csv \
  --metrics out/<дата>/metrics.json
```

`score_report.md` раскрывает коды, показывает медиану и межквартильный размах. Слушатель исключается, если оценил естественность REF ниже 70 более чем в половине фрагментов. Вариант проваливается при снижении медианы центра или окраски более чем на 10 пунктов либо если **форма** моно-суммы после вычитания среднего отклонения в диапазоне 200 Гц–5 кГц отличается от REF больше чем на 2 дБ хотя бы в одной 1/3-октавной полосе. Отчёт также приводит высокоразрешающую неравномерность по Велчу (8192 точки, 300 Гц–5 кГц); ориентир — не более 1 дБ пик-пик. Широкополосное изменение уровня само по себе не считается окраской. Успех — прирост медианы ширины или глубины минимум на 15 пунктов без провала.

## Диагностика алгоритмов на готовом рендере

Рендер из Android-приложения можно создать тем же JVM-источником обработки (телефон не требуется):

```bash
cd android
./gradlew :app:spatialRender --args="--in /путь/к/треку.wav --level soft --profile pair_wide --out /путь/к/результату"
cd ../tools/spatial-proto
python evaluate_algorithms.py /путь/к/результату --output /путь/к/анализу
```

В версии Android 1.9.0-s2 задача проверяет потоковый identity-тракт, поэтому варианты `W2_*` в `tracks/` совпадают
с REF. После добавления слоёв ширины и глубины эта же задача будет рендерить их из актуального DSP приложения.

```bash
python evaluate_algorithms.py out/ui/<run-id> --output out/evaluation
```

Команда повторно измеряет реальные WAV: LUFS, пик с передискретизацией 4×,
моно-спектр, отношение энергии Side/Mid и корреляцию каналов. Конфигурация берётся
из ключа рендера. Затем запускаются пробы на розовом шуме с пятью значениями
корреляции и тремя seed, сравнение фазового угла W3 на 12-секундных отрывках,
18 симуляций синхронизации с комнатой и дрейфом, проверка задержки и модельного
подавления перекрёстного сигнала XTC. Запуск занимает несколько минут.

Выходы: `evaluation.md`, `evaluation.json` с параметрами и SHA-256 музыкальных WAV,
`music_mono.png`. Исходные треки и оценки не меняются. Синтетические записи временные;
они не попадают в интерфейс как реальные замеры. Эти метрики не доказывают слышимую
ширину, глубину или сохранность центра в комнате. Для этого нужны слепые оценки
и запись реального воспроизведения. Отношение Side/Mid — только характеристика сигнала.

Результаты проверки Marcin и обнаруженные ограничения:
[отчёт 29 сентября 2026](reports/2026-09-29/README.md).

## 7. Отдельная проверка XTC на одном телефоне

```bash
python render.py /путь/к/jazz --xtc
```

Файлы появятся в `out/<дата>/xtc/tracks/`, ключ — в `out/<дата>/xtc/key.json`, шаблон — в `out/<дата>/xtc/scores_xtc.csv`. Перед рендером измерьте расстояние между динамиками и при необходимости измените `xtc.speaker_spacing_m` в конфиге. Воспроизводите варианты на Xiaomi 14 Ultra в горизонтальном положении на расстоянии 0,4 и 0,6 м. Системные эффекты Dolby и «улучшение звука» отключите. Сначала запустите `channel_id` и проверьте ориентацию динамиков. Соло-режим SoundField для этой проверки не требуется: подойдёт системный плеер. Для каждого кода поставьте оценки по тем же атрибутам и заполните `outside_phone` значением «да» или «нет».

## 8. Что настраивается

Все параметры вариантов, полос, когерентности, лимитера и XTC лежат в `config.yaml`. Фазовая декорреляция diffuse-сигнала работает в том же STFT, что и маска; `ambient.theta_max_deg` задаёт максимальный сдвиг фазы (по умолчанию 45°). ILD-защиту задают `stft.ild_direct_db` (по умолчанию 12 дБ) и `stft.ild_ramp_db` (6 дБ): при разнице каналов от 12 дБ рассеянный вес обнуляется, а в промежуточной зоне плавно уменьшается. `ambient.side_gain_db` (по умолчанию 2 дБ), `ambient.level_db` и D3-полка применяются к рассеянной части в спектре, без отдельной временной задержки.

Версия обработки — `PROTO_VERSION` в `render.py`; она записывается в ключи и отчёты. Перед передачей файлов слушателям оставьте `key.json` отдельно.

Модульные проверки DSP запускаются так:

```bash
python -m unittest discover -s tests -v
```
